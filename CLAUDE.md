# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is **雾凇拼音 (rime-ice)**, a comprehensive Rime input method configuration repository (github.com/iDvel/rime-ice). It provides ready-to-use configurations for the Rime Input Method Engine, including full pinyin, double pinyin, and T9 input schemas with large Chinese/English dictionaries and Lua extensions. It is config, not application code: there is no runtime to run, only Rime schemas/dictionaries/Lua plus a Go toolchain that maintains the dictionaries.

`AGENTS.md` is the authoritative agent contract — read it. The rules below restate its key constraints.

## Development Commands

All commands run from `others/script/` (use `make -C others/script/ <target>` from the repo root):

```bash
# Lint (requires: pip install yamllint; luarocks install luacheck)
make -C others/script lint          # YAML + Lua lint
make -C others/script lint-yaml     # YAML only (top-level *.yaml, excludes *.dict.yaml and .github/others/)
make -C others/script lint-lua      # Lua only (lua/**/*.lua via luacheck)

# Smoke test (runs in CI automatically; locally requires rime-cli and SMOKE_ALLOW_DESTRUCTIVE=1)
make -C others/script smoke         # suite: rime_ice

# Dictionary maintenance (requires Go 1.22+; takes ≥90s, prompts to confirm)
make -C others/script build         # Full pipeline: emoji → cn-en → pinyin → weight → check → polyphone → sort
```

`make smoke` deletes `build/` and `*.userdb` under the config root, so it needs `SMOKE_ALLOW_DESTRUCTIVE=1` for local runs. It auto-downloads `rime-cli` if the binary isn't found. Prefer running it in CI (where it's automatic) rather than locally against a live Rime user directory.

### Go script specific tasks (`cd others/script`)
```bash
go run main.go s    # Sort/dedup dictionaries only (skips the interactive confirm prompt)
go run main.go t    # Temporary test function
go run main.go tp   # Pinyin annotation for cn_dicts/temp.txt
```

`make build` runs `go run . --rime_path <repo> --auto_confirm`. Without `--auto_confirm` (e.g. plain `go run .`) it stops at an `Are you OK` prompt expecting `ok`/`y`/`yes`. Treat build warnings/errors as blocking — they must be fixed before committing (per AGENTS.md).

## CI Pipeline

- PRs and `workflow_dispatch`: lint + smoke test (`.github/workflows/test.yml`).
- Push to `main` or version tags (`[0-9]+.*`), excluding `.md`/`.gitignore`/`.github` changes: smoke → package → nightly release (`release.yml`).
- Dictionary maintenance runs in release CI when the commit message includes `[build]`; CI then auto-commits the generated results as `build(ci): auto build for -> …`.

## Architecture

### Core relationships

- `rime_ice.schema.yaml` is the main schema; it depends on `melt_eng` (English) and `radical_pinyin` (component lookup) as secondary translators.
- `t9.schema.yaml` depends on `rime_ice` — don't delete `rime_ice.schema.yaml` if T9 is in use.
- `double_pinyin_*.schema.yaml` variants are independent schemas sharing the same dictionaries.
- `rime_ice.dict.yaml` is the dictionary hub — it `import_tables` from `cn_dicts/` sub-dictionaries. Users add custom dictionaries by adding entries here.
- `default.yaml` controls which schemas are active, key bindings, menu, and punctuation. Bump `config_version` on any change so the new config overrides the user's shared Rime-directory copy on redeploy.
- `squirrel.yaml` (macOS/Squirrel) and `weasel.yaml` (Windows/Weasel) are frontend configs.

### Dictionary hub and placement (critical)

Edit the **source sub-dictionary**, never the hub. `*.dict.yaml` files are large — read the first ~100 lines then grep/locate; prefer find/replace/append over full rewrites.

- **Chinese → `cn_dicts/`** (do NOT edit `rime_ice.dict.yaml` directly):
  - `8105` — common single chars. `41448` — large char table, disabled by default.
  - `base` — core vocab; two-char words **must** go here; entries need pinyin + weight.
  - `ext` — extended vocab; **polyphone entries must go here**; entries need pinyin + weight.
  - `tencent` — large vocab; **no pinyin** (Rime auto-annotates), weight optional, **no polyphones**.
  - `others` — miscellaneous/fault-tolerant entries (e.g. colloquial pronunciations) imported by the hub; read the file header for its specific rules.
- **English → `en_dicts/*.dict.yaml`** (do NOT edit `melt_eng.dict.yaml` directly): `en` (core), `en_ext` (slang/net/product names/abbreviations).
- **Chinese-English mixed → edit `others/cn_en.txt` only**; `en_dicts/cn_en_*.txt` are generated by build.
- **Emoji → edit `others/emoji-map.txt` only**; `opencc/*.txt` are generated by build.

Dictionary entry format is tab-separated `汉字\t拼音\t权重`. Only entries after the marker line `# +_+` are processed by the maintenance script. Weight defaults to 100; adjust only for same-code (重码) collisions per common usage. When adding/editing a word: first `grep -r "目标词" <词典目录>/` to check existence, write to the correct file (order arbitrary), then run `make build` which sorts and dedups.

### Lua plugin integration

Lua files in `lua/` are referenced in schemas with the `*` prefix:
```yaml
- lua_translator@*date_translator
- lua_filter@*corrector
```
Filter ordering matters and is annotated inline (e.g. `pin_cand_filter` must precede emoji/simplifier). Schemas configure Lua behavior via top-level blocks (`date_translator:`, `lunar:`, `reduce_english_filter:`, `pin_cand_filter:`).

### Do-not-modify (synced from upstream)

`radical_pinyin.*.yaml` and `lua/search.lua` are synced from `mirtlecn/rime-radical-pinyin`. Report issues upstream, do not edit locally.

### OpenCC

`opencc/` holds emoji mappings and trad/simp conversion data used by the OpenCC filter. `emoji.txt`/`others.txt` are generated from `others/emoji-map.txt`.

## Key Conventions

### Customization pattern
End users create `.custom.yaml` patch files in their own Rime directory (not the repo) so configs survive `git pull`. The repo ships `rime_ice.custom.yaml`, `squirrel.custom.yaml`, `weasel.custom.yaml` as **example patches** — reference, not user-local overrides. Double-pinyin derivations differ from full-pinyin — see README "双拼" FAQ and `others/双拼补丁示例/`.

### Commit message format (Conventional Commits, Chinese body)
- `dict(cn)` / `dict(en)` / `dict(radical)` / `dict(opencc)` — dictionary edits by domain.
- `config` / `config(schema)` / `config(weasel)` — config/schema/frontend edits.
- `feat(lua)` / `fix(lua)` — Lua edits use the `lua` scope.
- Breaking change: add `!` after type/scope (e.g. `refactor(lua)!: …`) and update `others/docs/Changelog.md`.
- Include `[build]` in the message to trigger dictionary maintenance in release CI.

## Hard rules (from AGENTS.md)

- Do **not** delete any file. Do **not** modify `README.md`.
- Place edits in the correct file per "Dictionary hub and placement" above.
- After editing config/dictionaries, run the relevant `make` target and ensure it passes before committing.
- Before committing, confirm the working tree contains only files relevant to this task — no stray formatting or generated artifacts.
